# chatroom 网页聊天系统 — 测试总结报告

## 一、项目概述

chatroom 是一个基于 Spring Boot + MySQL + WebSocket 的网页聊天系统，提供用户注册、登录、搜索用户、好友申请/接受、创建会话、实时收发消息等核心功能。

本次测试覆盖功能、接口、UI、性能四个层面，采用手工与自动化结合的方式完成。

## 二、测试范围与策略

| 层面 | 方式 | 工具/框架 | 说明 |
|---|---|---|---|
| 功能测试 | 手工 | 浏览器 + Excel 用例管理 | 覆盖 6 大模块 + 权限场景 |
| 接口测试 | 自动化 | Python + pytest + requests + Allure | 48 条用例，含 HTTP 与 WebSocket 接口 |
| UI 测试 | 自动化 | Java + Selenium 4.18.1 + JUnit 4 | 15 条用例，覆盖登录→注册→加好友→建会话→发消息完整业务链路 |
| 性能测试 | 压测 | JMeter 5.6.3 | 登录/注册/搜索 3 个高频接口，并发 100~200 |

## 五、缺陷统计与分析

共发现缺陷 **7 个**，其中 6 个已修复并回归通过，1 个待修复；另有 1 条体验优化建议。

| 编号 | 缺陷描述 | 严重程度 | 状态 |
|---|---|---|---|
| BUG-001 | 注册超长用户名，后端返回系统错误码 9999，应为参数错误 1003 | 一般 | 已修复 |
| BUG-002 | 给不存在的用户发送好友请求无校验，产生"幽灵请求" | 一般 | 已修复 |
| BUG-003 | 多个接口缺少必填参数时返回 code=9999"系统繁忙"，应为 1003 参数错误（涉及发送/接受/拒绝好友请求、创建会话、历史消息等接口） | 严重 | 已修复 |
| BUG-004 | WebSocket 连接不校验会话归属，无效 sessionId 也能转发消息并落库 | 严重 | 已修复 |
| BUG-005 | WebSocket 消息内容超过 2048 字符时转发成功但落库失败，连接被断开 | 严重 | 已修复 |
| BUG-006 | 创建会话不校验好友关系，非好友也能创建会话 | 严重 | 已修复 |
| BUG-007 | 点击好友创建会话时弹出"参数类型错误：sessionId"错误框（前端先点击后创建会话的时序问题） | 轻微 | 待修复 |

- 另有 1 条建议优化：好友请求发送/接受成功后的弹窗提示为通用"操作成功"，建议改为具体提示语（"好友请求已发送"等），经评审不列入缺陷。

缺陷分布分析：缺陷集中在前端交互时序与后端参数/权限校验环节——早期缺少统一参数校验，多个接口缺失必填参数或字段超长时被兜底为 9999"系统繁忙"（BUG-001/003）；好友请求与 WebSocket 链路缺少存在性、归属、长度校验，产生幽灵数据（BUG-002/004/005/006）。修复后统一由全局异常处理器返回规范错误码，各链路增加前置校验。此类问题说明后端应建立统一的参数校验与权限校验机制，而非依赖各接口单独处理。

## 六、性能测试结果

| 接口 | 并发数 | 平均响应时间 | TPS | 错误率 | 结论 |
|---|---|---|---|---|---|
| 登录 /login | 200 | 2ms | 350/s | 0% | 通过 |
| 注册 /register | 100 | 5ms | 287/s | 0% | 通过 |
| 搜索 /searchUser | 100 | 1ms | 229/s | 0% | 通过 |

结论：并发 50→100→200 加压过程中，吞吐量稳定在 350/s 左右、响应时间毫秒级、错误率保持 0，未出现性能劣化拐点，当前单机环境性能表现良好。

## 七、测试结论

经多轮测试与修复迭代：核心业务链路（注册、登录、搜索、好友、会话、消息）功能正确性全部验证通过；63 条接口/UI 自动化用例全绿，回归稳定；性能测试三个高频接口在 100~200 并发下错误率均为 0、响应毫秒级，未出现性能劣化拐点。共发现缺陷 7 个，其中 6 个已修复并回归通过，1 个轻微缺陷（BUG-007）不影响主流程、待修复。本系统在测试范围内功能正确、性能稳定，达到可交付标准。

## 八、遗留问题

- BUG-007（轻微）：创建会话时错误弹窗，待前端调整时序后修复并回归。
- 性能测试基于单机本地环境，结果仅供参考，上线前建议在测试服务器环境复测。
- WebSocket 消息链路已通过接口自动化与 UI 双浏览器验证功能正确性，未做长连接专项性能压测。

## 九、个人总结

通过本次测试实践，完整走通了测试全流程：从测试点分析、用例设计，到 pytest 接口自动化框架搭建（fixtures 数据管理、自动清理、Allure 报告）、Java + Selenium UI 自动化（双浏览器验证业务链路、显式等待与弹窗处理）、JMeter 性能压测（并发梯度模型与响应断言）。过程中定位并推动修复 7 个缺陷，加深了对后端参数校验、WebSocket 通信机制和全局异常处理的理解，也积累了自动化用例稳定性方面的实战经验。
